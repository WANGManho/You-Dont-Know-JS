## 值类型

JS不把类型应用于变量或属性——我所说的"容器类型"——而是,值本身有类型——我所说的"值类型".

语言提供了七种内置,原始(非对象)值类型:[^PrimitiveValues]

* `undefined`
* `null`
* `boolean`
* `number`
* `bigint`
* `symbol`
* `string`

这些数值类型定义了一个或多个具体值的集合,每个集合都有一组针对每个类型的所有值的共享行为.

### 类型

任何值的值类型都可以通过`typeof`运算符,它总是返回 a`string`代表基本联署材料价值类型的价值:

```js
typeof true;            // "boolean"

typeof 42;              // "number"

typeof 42n;             // "bigint"

typeof Symbol("42");    // "symbol"
```

那个`typeof`运算符,当用到变量而不是值时,正在报告 * 变量中值的值类型 *:

```js
greeting = "Hello";
typeof greeting;        // "string"
```

JS变量本身没有类型. 它们具有任意性的价值,本身就有价值类型。

## 空值

### 与众不同

必须记住`null`和`undefined`*是* 实际上是不同的类型,因此`null`可明显区别于`undefined`。您可以仔细地构建程序,它们大多被视为不可区分。 但这需要开发商的关心和纪律。 从JS的观点来看,它们更经常是截然不同的.

有些情况下,`null`和`undefined`将触发语言的不同行为, 这很重要 记住。 我们不会详尽无遗地调查所有案件,但这里的例子如下:

```js
function greet(msg = "Hello") {
    console.log(msg);
}

greet();            // Hello
greet(undefined);   // Hello
greet("Hi");        // Hi

greet(null);        // null
```

那个`= ..`参数上的条款称为“参数默认值”。 它只有在该位置的参数缺失时,或者其默认值是准确的`undefined`数值。 如果你通过了`null`该条款不会触发,`null`因此被指定为参数。

没有正确或错误的方法`null`或`undefined`在一个程序。 因此,外卖是:在选择一种或另一种价值时要小心. 如果你可以互换使用,请特别小心。

### JS 字符编码

Unicode定义了所有在计算机程序中可以普遍代表的"特征",通过给每个代码分配一个特定的编号,称为代码点. 这些数字从`0`一直延续到`1114111` (`10FFFF`以十六进制计算。

Unicode 字符的标准注解为`U+`之后是4-6十六进制字符. 例如,`❤`(心脏符号)是密码点`10084` (`2764`在十六进制中),因此用`U+2764`.

Unicode中首组共65,535个代码点,称为BMP(Basic multiple plane). 这些都可以用16位(2字节)表示. 当代表来自BMP的Unicode字符时,这是相当直截了当的,因为他们可以*fit*整齐地组合成单一的UTF-16 JS字符.

其余所有代码点都归为16个,因此被称为"辅助飞机"或"星空飞机". 这些代码点需要超过16位来表示 -- -- 21位是精确的 -- -- 因此,在代表BMP以上的扩展/补充字符时,JS实际上将这些代码点作为两个相邻的16位代码单位的对称储存起来,称为*sorgee parts*(或*sorgee pairs*).

例如,Unicode 代码点`127878`(十六进制)`1F386`)为`🎆`(消防符号). JS将此存储在字符串值中,作为两个代位吸附码单元:`U+D83C`和`U+DF86`. 记住整个角色的这两个部分做 * 不 * 独立;它们只在紧邻对齐时才有效/有意义.

这对字符串的长度有影响,因为一个单独的可见字符像`🎆`烟花符号,在JS字符串中,为字符串长度的目的,算作2个字符!

##### 统一码

Unicode字符串处理中的另一个皱纹是,即使是某些单一的BMP字符也可以以不同的方式表示.

例如,`"é"`字符可以自行表示(代码点)`233`时,`\xe9`或`\u00e9`或`\u{e9}`),或作为两个代码点的组合:`"e"`字符( 代码点)`101`时,`\x65`, `\u0065`, `\u{65}`)和 * 组合图尔德 *(代码点)`769`时,`\u0301`, `\u{301}`).

考虑:

```js
eTilde1 = "é";
eTilde2 = "\u00e9";
eTilde3 = "\u0065\u0301";

console.log(eTilde1);       // é
console.log(eTilde2);       // é
console.log(eTilde3);       // é
```

指定的字符串文字`eTilde3`在此片段中将重音标记作为单独的*组合标记*符号存储。 和代对一样,一个结合标记只有在它相邻的符号(通常在之后)时才有意义.

无论如何,Unicode符号的渲染应是一样的,但如何`"é"`字符是内部存储的。`length`计算包含的字符串以及平等和关系比较(详见第二章):

```js
eTilde1.length;             // 2
eTilde2.length;             // 1
eTilde3.length;             // 2

eTilde1 === eTilde2;        // false
eTilde1 === eTilde3;        // true
```

一个特别的挑战是,你可以复制-粘贴一个字符串与`"é"`字符可见于其中,您复制的字符可能是在 *composed * 或 *decomposed * 形式中。 但是没有直观的方法可以分辨,然而文字中的基础字符串值会有所不同:

```js
"é" === "é";           // false!!
```

这种内部代表性差异可能相当具有挑战性,如果不是精心规划的话。 幸运的是,联署材料提供了`normalize(..)`用于帮助字符串的实用方法:

```js
eTilde1 = "é";
eTilde2 = "\u{e9}";
eTilde3 = "\u{65}\u{301}";

eTilde1.normalize("NFC") === eTilde2;
eTilde2.normalize("NFD") === eTilde3;
```

那个`"NFC"`正常化模式将相邻的代码点结合到*组合的*代码点(如果可能)中,而`"NFD"`正常化模式将一个单一的代码点拆分为其*分解的*代码点(如果可能的话).

而实际上可以有两个以上的单个*分解的*代码点构成一个单一的*分解的*代码点——例如,一个单一的字符可以对它应用几个截面标记.

在处理将比较,排序,或分析长度的Unicode字符串时,必须牢记Unicode正常化,并在必要时使用.

##### Unicode 图形集群

Unicode字符串处理的最终复杂之处是支持将多个相邻的代码点组合成一个单一的视觉显著的符号,称为*grapheme*(或*grapheme cluster*).

一个例子是家庭情感,例如:`"👩‍👩‍👦‍👦"`,它实际上由7个代码点组成,所有集群/组合为一个单一的视觉符号.

考虑:

```js
familyEmoji = "\u{1f469}\u{200d}\u{1f469}\u{200d}\u{1f466}\u{200d}\u{1f466}";

familyEmoji;            // 👩‍👩‍👦‍👦
```

这个emoji是*不是*一个单一的注册的Unicode代码点,因此没有*规范化*可以实现将这7个单独的代码点组成一个单一的实体. 这种复合符号的视觉渲染逻辑相当复杂,远远超出了大多数JS开发者想要嵌入我们程序的范围. 图书馆的确存在处理一些这种逻辑,但它们往往很大,仍然不一定涵盖所有的细微/变异.

与代配对和组合标记不同,石墨集群中的符号实际上可以作为独立的字符,但在放置相邻时具有特殊的组合行为.

这种复杂性严重影响长度的计算,比较,排序,以及许多其他常见的面向字符串的操作.

### 解析对强制

如果字符串值包含数字外观内容,您可能需要从该字符串值转换为`number`,用于数学操作目的.

然而,区分剖析转换和强制转换非常重要.

我们可以用JS的内置`parseInt(..)`或`parseFloat(..)`公用事业:

```js
someNumericText = "123.456";

parseInt(someNumericText,10);               // 123
parseFloat(someNumericText);                // 123.456

parseInt("42",10) === parseFloat("42");     // true

parseInt("512px");                          // 512
```

| 注: |
| :--- |
| 解析仅与字符串值相关,因为它是一个逐字符(左对右)的操作. 解析一下内容是没有道理的`boolean`,也不分析其中的内容`number`或一个`null`;没什么可分析的. 如果您将字符串值以外的东西传递到`parseInt(..)` / `parseFloat(..)`,这些公用设施首先将该值转换成字符串,然后尝试分析。 这几乎肯定有问题(导致虫子)或浪费 --`parseInt(42)`这是愚蠢的,和`parseInt(42.3)`滥用`parseInt(..)`来完成`Math.floor(..)`. |

解析从字符串值中抽出显示数字的字符,并将其放入`number`值,一旦遇到非数字字符即停止(例如,不是)`-`, `.`或`0`-`9`) (中文(简体) ). 如果在第一个字符上解析失败, 两个公用设备都会返回特殊字符`NaN`值(见下文“无效数字”),表示操作无效且失败。

何时`parseInt(..)`遇到`.`输入`"123.456"`它停止,使用仅仅`123`产生的结果`number`数值。`parseFloat(..)`对比接受这个`.`字符,并保持右侧解析浮点数后的任何小数位数`.`.

那个`parseInt(..)`特别是,将第二个论点视为可选的,但实际上*,相当必要,`radix`: 用于解释字符串字符的假设数字基数`number`(范围)`2` - `36`). `10`是标准基数-10,`2`用于二进制,`8`用于八进制,`16`是十六进制的 任何其他异常情况`radix`喜欢`23`假设数字顺序`0` - `9`接下来是`a` - `z`(案例不敏感) 字符协调。 如果指定的弧度位于`2` - `36`范围,`parseInt(..)`失败为无效并返回`NaN`数值。

若为`radix`被省略, 行为`parseInt(..)`相当细微和令人困惑,因为它试图根据它从第一个字符中看到的来为一个光圈做一个最好的猜测. 这在历史上导致了许多微妙的bug,所以从不依赖默认的自动猜测;总是指定一个明显的光度(比如:`10`(见以上电话)。

`parseFloat(..)`总是用弧度来描述`10`,所以没有接受第二个论点。

| 警报: |
| :--- |
| 令人惊讶的区别`parseInt(..)`和`parseFloat(..)`这是`parseInt(..)`将不完全解析科学标记(例如,`"1.23e+5"`),而不是停止在`.`因为它对整数无效;事实上,甚至`"1e+5"`停下来`"e"`. `parseFloat(..)`另一方面,完全按照预期来描述科学标记。 |

与剖析转换相反,强制转换是一种全或全无的操作. 字符串的全部内容被确认为数值(整数或浮点),或者整个转换失败(结果为`NaN`——再次,参见本章后面的"无效数字").

强制转换可明确采用`Number(..)`函数( 无)`new`关键词)或与 unary`+`值前的运算符:

```js

Number("512px");                // NaN
+"512px";                       // NaN
```

### 其他数字表示

除了使用传统的基数-10数字定义数字之外(`0`-`9`,JS支持在另外三个基数中定义全数字数:二进制(基数-2)、八进制(基数-8)和十六进制(基数-16)。

```js
// binary
myAge = 0b101010;
myAge;              // 42

// octal
myAge = 0o52;
myAge;              // 42

// hexadecimal
myAge = 0x2a;
myAge;              // 42
```

如你所见,前缀`0b`(二进制),`0o`(百分比)和`0x`(十六进制)在不同基数中定义数字的信号,但是在这些数字字数上不允许小数.

| 注: |
| :--- |
| JS 语法允许`0B`, `0O`,以及`0X`前缀也一样。 然而,请永远不要使用那些大写前缀表. 我认为任何理智的人都会同意:`0O`相较于一目了然`0o`(它本身,在视觉上有点模糊) 总是坚持小写前缀表! |

重要的是要认识到,你并没有定义一个"不同的数字",只是用不同的形式来产生相同的基础数字值.

默认情况下,JS以标准基数-10形式代表输出/字符串时态中的基本数值。 不过`number`值内置`toString(..)`在任何指定的碱基/半径中生成字符串表示的方法(如:`parseInt(..)`范围`2` - `36`):

```js
myAge = 42;

myAge.toString(2);          // "101010"
myAge.toString(8);          // "52"
myAge.toString(16);         // "2a"
myAge.toString(23);         // "1j"
myAge.toString(36);         // "16"
```

您可以将任意的光线字符串表达符回转到`number`使用`parseInt(..)`,带有适当的弧度:

```js
myAge = 42;

parseInt(myAge.toString("23"),23);      // 42
```

另一种指定数字文字的允许格式是使用科学标记:

```js
myAge = 4.2E1;      // or 4.2e1 or 4.2e+1

myAge;              // 42
```

`4.2E1`(或`4.2e1`表示,`4.2 * (10 ** 1)` (`10`页:1`1`权力。 责任人可以选择有一个标志`+`或`-`。如果该标志被省略,则假定是`+`。负函数使数字更小(左移小数),而不是大(右移小数):

```js
4.2E-3;             // 0.0042
```

这种科学标记形式对于可读性特别有用,因为可读性是指:`10`:

```js
someBigPowerOf10 = 1000000000;

// vs:

someBigPowerOf10 = 1e9;
```

默认情况下,JS会使用同样的科学标记来表示(例如作为字符串值等)非常大或非常小的数字 -- -- 具体来说,如果数值需要超过21位精确数字的话:

```js

ratherBigNumber.toString();     // "9.748913698143826e+22"

prettySmallNumber = 123 ** -11;
prettySmallNumber.toString();   // "1.0257553107587752e-23"
```

绝对值较小的数字(关闭到`0`) 超过这些阈值仍可能被迫采用科学标记形式(作为字符串):

```js
plainBoringNumber = 42;

plainBoringNumber.toExponential();      // "4.2e+1"
plainBoringNumber.toExponential(0);     // "4e+1"
plainBoringNumber.toExponential(4);     // "4.2000e+1"
```

可选参数`toExponential(..)`指定要包含在字符串表示式中的小数位数。

编码中指定数字字的另一种可读性是插入能力`_`成为数字分隔器,只要它方便/有意这样做。 例如:

```js
someBigPowerOf10 = 1_000_000_000;

totalCostInPennies = 123_45;  // vs 12_345
```

决定使用`12345`(无分隔符),`12_345`(如"12,345"),或`123_45`(如"123.45")完全由法典作者决定;JS忽略了分离者. 但根据背景`123_45`可能比传统的三位数组合方式更有意义(可读性明智)`12_345`.

### IEEE-754 二进制表达式

IEEE-754 (英语).[^IEEE754]是二进制表示小数的技术标准。 它被大多数计算机编程语言广泛使用,包括JS,Python,Ruby等.

这些位是左右排列的,如此(S = 签名位,E = 指示位,M = 曼提萨位):

```js

MMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMM
```

所以,号码`42`(或`42.000000`)将用这些比特表示:

00000000000000000000000000000000

符号位是`0`,表示数字为正数(`1`页:1

| 注: |

### 数量限制

现在看一看IEEE-754的操作情况可能很明显,数字基数的52位必须共享,既代表整个数字部分(如果有的话),也代表预定数字的小数部分(如果有的话).`number`数值。 基本上,要表示的整数部分越大,小数部分可用比特越少,反之亦然.

可准确存储在`number`类型以`Number.MAX_VALUE`:

```js
Number.MAX_VALUE;           // 1.7976931348623157e+308
```

你可能会期望这个值是十进制值, 考虑到代表。 但仔细检查一下`1.79E308`是(约)`2^1024 - 1`这看起来更像是整数 对吧? 我们可以核实:

```js
Number.isInteger(Number.MAX_VALUE);         // true
```

但是如果你超过最大值会怎么样?

```js
Number.MAX_VALUE === (Number.MAX_VALUE + 1);
// true -- oops!

Number.MAX_VALUE === (Number.MAX_VALUE + 10000000);
// true
```

这么说`Number.MAX_VALUE`在联署材料中代表的最大价值? 这当然是最大的 "无限"`number`数值。

IEEE-754定义了一种特别的无限价值,JS将其暴露为:`Infinity`还有一个`-Infinity`在数字线的另一端。 价值可以测试,看看它们是否是有限的或无限的:

```js
Number.isFinite(Number.MAX_VALUE);  // true

Number.isFinite(Infinity);          // false
Number.isFinite(-Infinity);         // false
```

永远不能向上数(与`+ 1`从。`Number.MAX_VALUE`改为:`Infinity`无论你让程序运行多久 因为`+ 1`操作实际上不会超过顶部`Number.MAX_VALUE`数值。

然而,联署材料的算术作业`+`, `*`,甚至`/`绝对可以溢出`number`上端键,在这种情况下`Infinity`结果是:

```js
Number.MAX_VALUE + 1E291;           // 1.7976931348623157e+308
Number.MAX_VALUE + 1E292;           // Infinity

Number.MAX_VALUE * 1.0000000001;    // Infinity

1 / 1E-308;                         // 1e+308
1 / 1E-309;                         // Infinity
```

| 提普: |
| :--- |
| 反之则不然:在无限值上进行算术操作*永远不会*产生有限值. |

从非常大到非常小--实际上,最接近零,这和去非常,非常消极的不一样! - 理论上可以存储在`number`类型是`2^-1022`(还记得IEEE-754 缩写范围吗?),或围绕.`2E-308`然而,JS引擎根据规格允许其内部代表对这一下限有不同的表述。 不管引擎的有效下限是什么 它都会暴露为`Number.MIN_VALUE`:

```js
Number.MIN_VALUE;               // 5e-324 <-- usually!
```

大部分JS引擎 似乎有最小的可代表价值`5E-324`(约`2^-1074`) (中文(简体) ). 根据引擎和/或平台的不同,可能会暴露出不同的值. 注意任何依赖于这种执行依赖值的程序逻辑.

### 安全整数限制

从`Number.MAX_VALUE`是一个整数,你可能认为它是语言中最大的整数。 但这并不准确。

您可以准确存储的最大整数`number`类型是`2^53 - 1`,或`9007199254740991`,它比`Number.MAX_VALUE`(约`2^1024 - 1`) (中文(简体) ). 这个特殊的更安全值被曝光为`Number.MAX_SAFE_INTEGER`:

```js
maxInt = Number.MAX_SAFE_INTEGER;

maxInt;             // 9007199254740991

maxInt + 1;         // 9007199254740992

maxInt + 2;         // 9007199254740992
```

我们看到整数大于`9007199254740991`可以现身. 然而,这些较大的整数并不是"安全"的,因为精度/精确度在操作时开始分解. 如上所示,`maxInt + 1`和`maxInt + 2`两种表达方式都错误地给出了相同的结果,说明了超过`Number.MAX_SAFE_INTEGER`限制。

但最小的安全整数是什么?

根据你如何解释"最小", 你可以回答`0`还是...`Number.MIN_SAFE_INTEGER`:

```js
Number.MIN_SAFE_INTEGER;    // -9007199254740991
```

JS 提供了一种工具来确定一个值是否是这个安全范围内的整数(`-2^53 + 1` - `2^53 - 1`):

```js
Number.isSafeInteger(2 ** 53);      // false
Number.isSafeInteger(2 ** 53 - 1);  // true
```

### 双零

你可能惊讶地知道JS有两个零:`0`,以及`-0`(负零). 但什么是"负零"?[^SignedZero]一个数学家肯定会对这个概念置若罔闻。

这不仅仅是个有趣的JS怪怪的;它是由IEEE-754授权的[^IEEE754]规格。 所有浮点数都签名,包括0. 尽管JS确实隐瞒了存在`-0`完全有可能产生并检测到:

```js
function isNegZero(v) {
    return v == 0 && (1 / v) == -Infinity;
}

regZero = 0 / 1;
negZero = 0 / -1;

regZero === negZero;        // true -- oops!
Object.is(-0,regZero);      // false -- phew!
Object.is(-0,negZero);      // true

isNegZero(regZero);         // false
isNegZero(negZero);         // true
```

你可能想知道我们为什么需要这样的东西`-0`。当使用数字既能代表某些物品的移动幅度(速度)(如游戏字符或动画),又能代表其方向(如负=左,正=右)时,可以有所帮助.

在没有签名的零值的情况下,你无法分辨这种物品在休息时指向哪个方向。

| 注: |
| :--- |
| 联合来文在《任择议定书》中定义了签名的零。`number`类型,在`bigint`数字类型。 因此,`-0n`被解释为`0n`,两者是不可分的. |

### 无效的数字

数学操作有时会产生无效的结果. 例如:

```js
42 / "Kyle";            // NaN
```

这可能是显而易见的,但是如果你试图用字符串来划分一个数字,那是一种无效的数学操作.

另一种无效的数字操作是试图强制将非数字的类似值转换为`number`如前所述,我们可以通过下列两种办法:`Number(..)`函数或无`+`运算符:

```js
myAge = Number("just a number");

myAge;                  // NaN

+undefined;             // NaN
```

所有这些无效操作(数学或强制/数字)都会产生特殊性`number`调用值`NaN`.

"纳恩"的历史根源(来自IEEE-754)[^IEEE754]规格)作为"非数字"的缩写. 从技术上讲,64位的IEEE-754数字空间中约有9个四角星值被指定为"NaN",但JS却将所有它们作为单数对待.`NaN`数值。

不幸的是,这并不意味着造成混乱,因为`NaN`*绝对* a`number`.

* "iNvalid数字"
* "实际数字"

`NaN`这是JS的一个特殊价值,因为它是语言中唯一缺少"身份属性"的价值——它永远不能与自己平等.

所以不幸的是,`===`运算符无法检查值是否为`NaN`但有一些方法可以做到:

如果你没有正确检查`NaN`在你做数学或数字转换的程序中,我可以有一定把握地说:你可能在某个地方的程序中有一个数字错误,它只是还没有咬你(你知道!).

## 大整数值

作为JS的最大安全整数`number`这是`9007199254740991`(见上文),如果JS程序需要进行更大的整数数学,甚至仅仅持有像64位整数ID(如Twitter Tweet ID)这样的值,那么这样的相对低限就会产生问题.

为此,联署材料提供了候补法官。`bigint`类型(BigInteger),它可以任意存储大型(理论上不受限制,但有限的机器内存和/或JS执行除外)整数。

区分a`bigint`从整体(整数)`number`值,否则两者看起来相同(`42`联合来文要求`n`打开后缀`bigint`数值:

```js
myAge = 42n;        // this is a bigint, not a number

myKidsAge = 11;     // this is a number, not a bigint
```

让我们来说明上层的无约束性`bigint`:

```js
Number.MAX_SAFE_INTEGER;        // 9007199254740991

Number.MAX_SAFE_INTEGER + 2;    // 9007199254740992 -- oops!

myBigInt = 9007199254740991n;

myBigInt + 2n;                  // 9007199254740993n -- phew!

myBigInt ** 2n;                 // 81129638414606663681390495662081n
```

如你所见`bigint`值类型能够进行精确的算术,超过整数极限`number`值类型。

| 警报: |
| :--- |
| 注意到`+`需要运算符`.. + 2n`而不是仅仅`.. + 2`无法混合`number`和`bigint`在同一表达式中的值类型。 这个限制很烦人,但是它保护了您的程序免受无效的数学操作,这些操作会给出非明显的意外结果. |

页:1`bigint`值也可以随`BigInt(..)`函数; 例如, 转换一个整体( 整数)`number`值为 a`bigint`:

```js
myAge = 42n;

inc = 1;

myAge += BigInt(inc);

myAge;              // 43n
```

| 警报: |
| :--- |
| 虽然对于一些读者来说,这似乎是反直觉的,`BigInt(..)`总是没有`new`关键词 若为`new`中,将丢弃例外。 |

这绝对是最常用的习惯之一`BigInt(..)`函数: 转换`number`升为`bigint`s,用于数学操作目的.

但代表大整数值作为字符串并不罕见,特别是当这些值从其他语言环境进入JS环境,或者通过某些交换格式,而这些交换格式本身并不支持.`bigint`- 典型的价值观。

因此,`BigInt(..)`用于强制这些字符串值`bigint`编号:

```js
myBigInt = BigInt("12345678901234567890");

myBigInt;                       // 12345678901234567890n
```

与`parseInt(..)`,如果字符串中的任何字符都是非数字(`0-9`数字或`-`,包括:`.`甚至是跟踪`n`后缀字符,将丢出一个例外。 也就是说,`BigInt(..)`是一种完全或完全的强迫性转变,而不是解释性的转变。

那个`symbol`类型包含特殊的不透明值,称为“符号”。 这些值只能由`Symbol(..)`函数:

```js
secret = Symbol("my secret");
```

| :--- |
| 碞钩妓`BigInt(..)`,则`Symbol(..)`函数必须调用,而不使用`new`关键词 |

那个`"my secret"`字符串传入`Symbol(..)`函数调用不是 * * 符号值本身,尽管它似乎是这样。 它只是一种可选的描述性标签,只用于调试目的,以有利于开发者.

从`Symbol(..)`它是一种特殊的价值,它抵制 程序/开发者检查 任何关于它的基本代表。 我意思是"不干净"

| 注: |
| :--- |
| 你可以把符号想象成是单调的增量整数-- 事实上,这和一些JS引擎执行它们的方式相似。 但JS引擎绝不会以你或程序所能看到的任何方式 暴露一个符号的基本价值的任何表现. |

符号由JS引擎保证是独一无二的(只在程序本身内),并且是令人厌恶的. 换句话说,一个程序的重复符号值永远无法创建.

你可能想知道现在用什么符号?

一个典型的用法是作为"特殊"的值,开发者将其区别于可能意外碰撞的任何其他值. 例如:

```js
EMPTY = Symbol("not set yet");
myNickname = EMPTY;

// later:

if (myNickname == EMPTY) {
    // ..
}
```

在这里,我定义了一个特殊的`EMPTY`价值和初始化`myNickname`对它。 稍后,我检查一下它是否还那么特别的价值, 然后做一些动作,如果是这样。 我也许不想用`null`或`undefined`为此,另一个开发商也许能够通过其中一种共同内置值。`EMPTY`相比之下,这里是一个独特的,令人厌恶的价值观,只有我定义了,并且有控制权和进入权.

也许更常见的是,符号常被用作对象上的特殊(meta-)属性:

```js
myInfo = {
    name: "Kyle Simpson",
    nickname: "getify",
    age: 42
};

// later:
PRIVATE_ID = Symbol("private unique ID, don't touch!");

myInfo[PRIVATE_ID] = generateID();
```

需要注意的是,符号属性仍然在任何物体上公开可见;它们并不是*实际上*私有的. 但是,它们被作为特殊和设定处理,与通常的物体属性收集不同. 和以前一样

```js
Object.defineProperty(myInfo,"__private_id_dont_touch",{
    value: generateID(),
    enumerable: false,
});
```

多数开发者只通过惯例知道,如果一个属性名称的前缀是`_`(甚至更是这样,`__`这说明这是"私人的" 除非他们真的应该访问它 否则别管它

符号基本上服务于相同的使用大小写,但比前缀方法在工程学上要多一点.

### 熟知符号 (WKS)

JS预定义了一组符号,称为*熟知符号*(WKS),代表物体上某些特殊的元编程钩. 这些符号作为静态属性存储于`Symbol`函数对象。 例如:

```js
myInfo = {
    // ..
};

String(myInfo);         // [object Object]

myInfo[Symbol.toStringTag] = "my-info";
String(myInfo);         // [object my-info]
```

`Symbol.toStringTag`是访问和压倒一个普通对象的默认字符串代表的知名符号(`"[object Object]"`),替换`"Object"`具有不同价值的部分(例如,`"my-info"`).

请参看本系列的"Objects & Classes"一书,了解更多关于Well-Known符号和元编程的信息.

### 全球符号登记册

通常,您想要保持符号值的私有性,比如在模块范围内. 但偶尔,你想揭露他们 这样他们就可以从全球范围 进入JS程序的所有文件

而不是仅仅把它们作为全球变量(即:`globalThis`共同意见(object),JS提供了替代的 * 全球命名空间*,用于注册下列文件中的符号:

```js
// retrieve if already registered,
// otherwise register
PRIVATE_ID = Symbol.for("private-id");

// elsewhere:

privateIDKey = Symbol.keyFor(PRIVATE_ID);
privateIDKey;           // "private-id"

// elsewhere:

// retrieve symbol from registry undeer
// specified key
privateIDSymbol = Symbol.for(privateIDKey);
```

转至的值`Symbol.for(..)`*不* 与过去一样`Symbol(..)`. `Symbol.for(..)`期望在全球登记册下登记该符号的唯一的 * 关键 *,而`Symbol(..)`可选择接受描述性标签(不一定是唯一)。

如果登记簿在指定的*key*下没有符号,则在那里创建一个新的符号(没有描述性标签)并自动登记。 否则`Symbol.for(..)`返回先前已注册的符号。

向相反方向走,如果你有符号值本身, 想取回*键* 它注册在,`Symbol.keyFor(..)`将符号本身作为输入,返回 * 键 *(如果有的话)。 这对于绕过*key*字符串值比符号本身更方便,是有用的.

### 物体还是原始的?

不像其他原始人喜欢`42`,其中可以创建多个相同值的拷贝,符号 *do* 行为更像特定对象的参考,因为它们总是完全独特的(为了价值分配和平等比较的目的). 规格还把`Symbol()`函数在“基本对象”部分下,称为“构建者”,甚至定义其`prototype`属性。

然而,如前所述,`new`无法使用`Symbol(..)`; 这类似于`BigInt()`"建筑师". 我们很清楚`bigint`价值是原始的,所以`symbol`价值似乎相同。

而在规格的"术语与定义"中,它将符号列为原始值.[^PrimitiveValues]此外,这些价值本身在联署材料的方案中被用作原始的而不是物体。 例如,符号主要作为对象中的密钥使用——我们知道对象不能使用其他对象值作为密钥! - 和弦,它们也是原始的。

如前所述,一些JS引擎甚至内部执行符号作为独特的单调递增整数(primitives!).

最后,正如本章顶部所解释的,我们知道原始值是*不允许*在其上设置属性的,而是*自动装箱*(参见第三章中的"自动对象")在内部与相应的对象-切换器类型,以便于属性/方法访问. 符号跟随所有这些确切的行为,和其他所有原始人一样.

所有这一切,我认为符号是 * much more * 像原始人而不是物体, 所以我在这本书中介绍它们。
